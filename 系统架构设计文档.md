# 进销存系统 - 架构设计文档

> **架构方案：独立 Flutter 前端 + 单一 Go 后端 + 多数据库多租户**

---

## 一、架构概览

### 1.1 核心约束

| 约束 | 方案 |
|---|---|
| 前端 | Flutter 独立仓库，Web + Windows 双端 |
| 后端 | 单一 Go 服务（一个二进制、一个进程） |
| 数据库 | 多个独立 MySQL 库，按业务域隔离 |
| 多租户 | 商户（Tenant）为核心，用户是附属操作员 |

## 二、多租户模型

### 2.1 商户（Tenant）架构

> **核心原则：商户（生意主体）为核心，账号（自然人）是附属操作员。**
> 一个商户 = 一套独立进销存账；商品、库存、单据、资金、报表全部属于商户，不属于任何个人。
> 一个账号可加入多个商户，登录后选定「当前商户」，权限按商户分别分配。

```
┌─────────────────────────────────────────────────────────────────┐
│                        mysql_main（主库 · 账号与商户）            │
│                                                                 │
│   ┌──────────┐        ┌──────────┐        ┌──────────┐          │
│   │  users   │        │ tenants  │───────>│  plans   │          │
│   │ (自然人) │        │ (商户)   │  plan  │ (套餐)   │          │
│   └────┬─────┘        └────┬─────┘        └──────────┘          │
│        │                   │                                     │
│        │    ┌──────────────┴──────────────┐                     │
│        └───>│        user_tenants          │<──── is_owner 主账号 │
│     N:1     │ (用户-商户成员关系+角色权限)   │      role 角色        │
│             └──────────────┬──────────────┘      permissions 权限  │
│                            │ 1:N                                 │
│                     ┌──────┴──────┐                             │
│                     │    shops    │  (门店)                      │
│                     └─────────────┘                             │
│                                                                 │
│   tenant_configs (商户业务配置)   tenant_invitations (邀请)       │
└─────────────────────────────────────────────────────────────────┘
                          │
                          │ tenant_id ( + shop_id )
                          ▼
┌─────────────────────────────────────────────────────────────────┐
│                 mysql_shop（零售进销存库 · 业务数据）             │
│                                                                 │
│  所有业务表都带 tenant_id（多门店再加 shop_id）                  │
│  不同商户的数据在同一库中，通过 tenant_id 逻辑隔离               │
│                                                                 │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐          │
│  │  goods   │ │ customers│ │  sales   │ │ purchases│          │
│  │  商品    │ │  客户    │ │  销货单   │ │  购货单   │          │
│  └──────────┘ └──────────┘ └──────────┘ └──────────┘          │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐          │
│  │ suppliers│ │  stock   │ │ accounts │ │warehouses│          │
│  │  供应商  │ │  库存    │ │  账户    │ │  仓库    │          │
│  └──────────┘ └──────────┘ └──────────┘ └──────────┘          │
└─────────────────────────────────────────────────────────────────┘
```

**说明**
- `users`、`tenants`、`user_tenants`、`shops`、`plans` **全部位于主库 `mysql_main`**；业务库 `mysql_shop` 不含用户表
- 账号不携带业务数据；换商户即换 `tenant_id`，看到的是另一套账

### 2.2 租户隔离策略

| 层级 | 策略 | 说明 |
|---|---|---|
| 数据库级 | 同库不同表 | 所有商户数据在同一 MySQL 库 |
| 表级 | tenant_id 字段 | 每张业务表都有 tenant_id；多门店业务再加 shop_id |
| 应用级 | 中间件自动注入 | 解析 JWT → 校验 `user_tenants` 成员关系 → 注入 tenant_id/shop_id/role |
| 权限级 | 按商户授权 | 同一账号在不同商户拥有不同的 role 与 permissions |
| 限额级 | 套餐校验 | 建商品/加员工/开单/建店时按 `plans` 校验上限 |
| API 纯净 | 路由分组 | /api/shop/* 自动绑定零售库 |

### 2.3 关键模型关系

```
┌──────────────┐        ┌──────────────┐
│    Plan      │<──plan──│   Tenant     │ ← 商户（业务主体·核心）
│   (套餐)     │        │   (商户)     │
└──────────────┘        └──────┬───────┘
                               │ 1:N
        ┌──────────────────────┼──────────────────────┐
        │                      │                      │
        ▼                      ▼                      ▼
 ┌──────────────┐      ┌──────────────┐      ┌──────────────┐
 │    Shop      │      │  UserTenant  │      │ 所有业务表    │

                       └──────────────┘
```

### 2.4 账号可加入多个商户

一个人（自然人账号）可以同时是多个商户的成员；**账号本身不携带任何业务数据**，商品/库存/单据属于商户。

```
         ┌───────────────┐
         │  张三（账号）  │  ← 自然人，手机号登录
         └───────┬───────┘
                 │
        ┌────────┴────────┐
        ▼                 ▼
 ┌─────────────┐   ┌─────────────┐
 │ 商户 A 五金店│   │ 商户 B 便利店│
 │ is_owner=1  │   │ is_owner=0  │
 │ role=管理员  │   │ role=收银员  │
 │ 商品/单据/账 │   │ 商品/单据/账 │
 └─────────────┘   └─────────────┘
        ▲                 ▲
        │ 邀请            │ 邀请
        └────────┬────────┘
                 │
         ┌───────┴───────┐
         │  李四（账号）  │
         │ A店: 操作员    │
         │ B店: 管理员    │
         └───────────────┘
```

- 张三创建商户 A → 自动成为 A 的**主账号**（`is_owner=1`）
- 张三邀请李四加入 A → 李四在 A 内是操作员（只能开销售单）
- 李四同时被另一个老板邀请加入商户 B → 在 B 内拥有另一套权限
- **A、B 两套账数据完全隔离，互不可见**

### 2.5 当前商户与切换机制

采用「**切换商户时重新签发 Token**」方案：

```
登录 login
  → 返回该账号所属商户列表 [{tenant_id, name, role}]
  → 前端选择/默认上次活跃商户
  → 签发 JWT：{ user_id, tenant_id, shop_id, role, exp }

创建商户 create-tenant（已登录账号再开一套账）
  → 校验套餐/账号状态，创建 tenants 记录（owner_user_id = 当前 user）
  → 写入 user_tenants（is_owner=1, role=超级管理员）
  → 复制套餐限额快照（max_*）
  → 重新签发绑定新 tenant_id 的 JWT
  → 前端把新商户加入下拉并切过去

切换商户 switch-tenant
  → 校验 user_tenants 成员关系与 status
  → 重新签发绑定新 tenant_id 的 JWT
  → 前端丢弃旧 Token，后续请求全部落到新商户

每个请求
  → TenantMiddleware 解析 JWT
  → 校验 user_tenants(user_id, tenant_id) 有效
  → 注入 tenant_id / shop_id / role 到上下文
  → Repository 层自动带 tenant_id 过滤
```

## 三、数据库设计

### 3.1 主库（mysql_main）

> 主库承载**账号与商户**：`plans / tenants / users / user_tenants / shops / tenant_invitations / tenant_configs`。
> 业务数据（商品/库存/单据/资金）在 `mysql_shop`，仅通过 `tenant_id` 关联。

#### plans（套餐表）

```sql
CREATE TABLE plans (
    id              BIGINT PRIMARY KEY,
    code            VARCHAR(50) NOT NULL COMMENT '套餐编码 free/open/single/multi',
    name            VARCHAR(100) NOT NULL COMMENT '套餐名称',
    price           DECIMAL(10,2) DEFAULT 0 COMMENT '价格(元/年)',
    max_goods       INT DEFAULT 100 COMMENT '商品上限(0=不限)',
    max_staff       INT DEFAULT 1 COMMENT '员工账号上限(0=不限)',
    max_shops       INT DEFAULT 1 COMMENT '门店上限(0=不限)',
    max_orders      INT DEFAULT 0 COMMENT '单据上限(0=不限)',
    features        JSON COMMENT '功能开关',
    sort            INT DEFAULT 0,
    status          TINYINT DEFAULT 1,
    created_at      DATETIME DEFAULT CURRENT_TIMESTAMP,

    UNIQUE KEY uk_code (code)
) COMMENT '套餐表';
```

#### tenants（商户表）

```sql
CREATE TABLE tenants (
    id              BIGINT PRIMARY KEY,
    name            VARCHAR(200) NOT NULL COMMENT '商户名称',
    type            TINYINT DEFAULT 1 COMMENT '1=个体户 2=有限公司 3=合伙企业',
    contact_name    VARCHAR(50) COMMENT '联系人',
    contact_phone   VARCHAR(20) COMMENT '联系电话',
    owner_user_id   BIGINT COMMENT '主账号(老板)用户ID',
    plan_id         BIGINT COMMENT '当前套餐',
    plan_expires_at DATETIME COMMENT '套餐到期时间',
    max_goods       INT DEFAULT 100 COMMENT '商品上限(套餐快照)',
    max_staff       INT DEFAULT 1 COMMENT '员工账号上限(套餐快照)',
    max_shops       INT DEFAULT 1 COMMENT '门店上限(套餐快照)',
    max_orders      INT DEFAULT 0 COMMENT '单据上限(套餐快照,0=不限)',
    status          TINYINT DEFAULT 1 COMMENT '1=正常 0=冻结 -1=注销',
    created_at      DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at      DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,

    INDEX idx_status (status),
    INDEX idx_plan (plan_id, plan_expires_at),
    INDEX idx_owner (owner_user_id)
) COMMENT '商户表(业务主体)';
```

> `max_*` 为套餐限额快照：绑定/升级套餐时从 `plans` 复制，也可单独覆盖。

#### users（用户表·自然人）


#### user_tenants（用户-商户成员关系表）


```go
// internal/db/mysql.go - 多数据库连接池
package db

import (
    "database/sql"
    "sync"
)

type DBType string

const (
    DBMain    DBType = "main"    // 主库(用户/租户)
    DBShop    DBType = "shop"    // 零售进销存
    DBIndustry DBType = "industry" // 工贸
)

type Manager struct {
    pools map[DBType]*sql.DB
    mu    sync.RWMutex
}

func NewManager(databases map[DBType]DatabaseConfig) *Manager {
    m := &Manager{pools: make(map[DBType]*sql.DB)}
    for dbType, cfg := range databases {
        db, err := sql.Open("mysql", cfg.DSN)
        if err != nil {
            log.Fatalf("Failed to connect to %s: %v", dbType, err)
        }
        db.SetMaxOpenConns(cfg.MaxOpenConns)
        db.SetMaxIdleConns(cfg.MaxIdleConns)
        m.pools[dbType] = db
    }
    return m
}

func (m *Manager) GetDB(dbType DBType) *sql.DB {
    m.mu.RLock()
    defer m.mu.RUnlock()
    return m.pools[dbType]
}
```

```go
// internal/middleware/tenant.go - 租户上下文注入
package middleware

import (
    "net/http"
    "context"
    "pisa_server/internal/pkg/jwt"
)

// JWT 载荷示例（切换商户时重新签发）
// {
//   "user_id":   10001,      // 自然人账号
//   "tenant_id": 20001,      // 当前商户（核心）
//   "shop_id":   30001,      // 当前门店（可空）
//   "role":      2,          // 在该商户下的角色
//   "exp":       1790000000
// }

func TenantMiddleware(memberRepo *repository.MemberRepository) gin.HandlerFunc {
    return func(c *gin.Context) {
        claims, err := jwt.ParseToken(c.GetHeader("Authorization"))
        if err != nil || claims.TenantID == 0 {
            c.JSON(http.StatusUnauthorized, gin.H{"error": "unauthorized"})
            c.Abort()
            return
        }

        // 校验账号确实是该商户成员且未被禁用（防止跨商户越权）
        member, err := memberRepo.Find(c.Request.Context(), claims.UserID, claims.TenantID)
        if err != nil || member == nil || member.Status != 1 {
            c.JSON(http.StatusForbidden, gin.H{"error": "not a member of this tenant"})
            c.Abort()
            return
        }

        // 注入商户上下文（role 以库中为准，避免 Token 提权）
        ctx := context.WithValue(c.Request.Context(), "tenant_id", claims.TenantID)
        ctx = context.WithValue(ctx, "user_id", claims.UserID)
        ctx = context.WithValue(ctx, "shop_id", claims.ShopID)
        ctx = context.WithValue(ctx, "role", member.Role)
        ctx = context.WithValue(ctx, "is_owner", member.IsOwner)
        c.Request = c.Request.WithContext(ctx)

        c.Next()
    }
}

// PlanLimitMiddleware 套餐限额校验：建商品/加员工/开单/建店前调用
func PlanLimitMiddleware(checker *service.PlanLimitChecker, resource string) gin.HandlerFunc {
    return func(c *gin.Context) {
        tenantID := c.Request.Context().Value("tenant_id").(int64)
        if err := checker.Check(c.Request.Context(), tenantID, resource); err != nil {
            c.JSON(http.StatusForbidden, gin.H{"error": err.Error(), "code": "PLAN_LIMIT_EXCEEDED"})
            c.Abort()
            return
        }
        c.Next()
    }
}
```

```dart
final apiClientProvider = Provider<ApiClient>((ref) {
  return ApiClient();

class ApiClient {
  late final Dio _dio;

  ApiClient() {
    _dio = Dio(BaseOptions(
      baseUrl: 'http://localhost:8080/api',
      connectTimeout: const Duration(seconds: 10),
      receiveTimeout: const Duration(seconds: 10),
    ));

    _dio.interceptors.addAll([
      AuthInterceptor(),
      LogInterceptor(),
    ]);
  }

  Future<Response> get(String path, {Map<String, dynamic>? queryParameters}) {
    return _dio.get(path, queryParameters: queryParameters);
  }

  Future<Response> post(String path, {dynamic data}) {
    return _dio.post(path, data: data);
  }

  Future<Response> put(String path, {dynamic data}) {
    return _dio.put(path, data: data);
  }

  Future<Response> delete(String path) {
    return _dio.delete(path);
  }
}
```
